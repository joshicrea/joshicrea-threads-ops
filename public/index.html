    同じジャンルで反応を集めている投稿を探し、1件ずつ Threads のページを開いて、全文と実際のいいね・返信数を確かめます。確かめられた日本語の投稿だけを残し、反応の大きい順に5件を投稿生成の参考として自動で使い、型を分析します。1テーマで5〜10分ほど、最大20分で打ち切りです。この画面を離れても裏で進みます（パソコンに Chrome か Microsoft Edge が要ります）。

    1件ずつ探す・貼り付ける

    反応数（いいね・返信）は、Threads の権限が付いているときだけ自動で取れます。取れない投稿は「反応数なし」と表示し、0とは扱いません。下限を入れると、反応数が取れた投稿のうち、下限に届かないものを候補に入れません。

    キーワードで投稿を探して候補に追加します。今は他の人の投稿を直接検索できないため、見つからないときはWeb検索で探します（最大8件・1〜3分）。それでも見つからない場合は、下の「手動で貼り付け」を使ってください。

    改善提案

    1. AI（文章生成）

    このPCにインストール済みの Claude Code を裏で呼びます。Claude Code でログイン済みなら追加設定は不要です。利用量は Claude の契約枠から消費されます。

    このPCにインストール済みの Codex CLI（OpenAI）を裏で呼びます。ターミナルで codex を起動して ChatGPT アカウントでログイン済みなら追加設定は不要です。利用量は ChatGPT の契約枠から消費されます（1回あたり Claude Code より多め）。Webで集めた参考・参考投稿の Web検索も使えます。

    無料枠には1分あたり・1日あたりの回数制限があります。上限に達すると自動で待って再試行しますが、続けて使う場合はGoogle AI Studioで課金設定を入れてください。

    Webで集めた参考の検索（Google検索）は Claude API では使えません。参考投稿のThreads検索・手動貼り付けは使えます。

    2. Threads連携

    この画面を渡した運営者（林）からメッセージで届く、TOPS1. で始まる1行を、全部そのまま貼って、画面下の「設定を保存」を押します。LINEやメールのほかの人にも見せないでください。

    詳しい設定（運営者に言われたときだけ触る）
    先に連携コードを入れて保存します
    設定手順（Meta アプリを自分で作る場合だけ。運営者から連携コードが届いた方は読まなくてよい）
    1. Meta for Developers でアプリを作成し、ユースケースに Threads API を追加する
    2. 左メニュー「ユースケース」→ Threads API の「設定」を開く。ここに表示される Threads App ID と Threads App Secret を使う（「アプリの設定 → ベーシック」のアプリIDを使うと「アプリIDが送信されませんでした」エラーになる）
    3. 同じ画面の「Redirect Callback URLs」に https://localhost:4174/oauth/callback を登録して保存する（Meta は https しか受け付けない。このツールが自己署名証明書で https://localhost:4174 を立てる）。localhost だと「フォームを保存できません」になる場合は、ツール同梱の relay フォルダの4ファイルを自分の公開サイトに置き、その公開URLを Meta の3欄と上の Redirect URI に入れる（relay/README.md 参照）
    4. Threads App ID と Secret を上に貼り、「設定を保存」を押す
    5. 「Threadsと連携する」を押し、Threads側で許可する（Threadsアプリの「設定 → アカウント → ウェブサイトの権限 → テスター招待」で自分のアカウントをテスターに追加しておく必要がある場合がある）
    6. 許可後、ブラウザに「この接続ではプライバシーが保護されません」と出たら「詳細設定」→「localhost にアクセスする」を押す（自己署名証明書のため。localhost 内で完結するので外部には出ない）
    7. 「Threadsと連携しました」と表示されたら、この画面で「再読み込み」
    8. うまくいかない場合の代替: Meta の Threads API 設定画面にある「ユーザートークン生成ツール」で自分のアカウントのトークンを発行し、上の「アクセストークン（手動で貼る場合のみ）」に貼って保存する

    3. 発信者

    フォルダ直下の .md と .txt を読んで投稿の素材にします（内容はAIに送られます。見られたくないファイルは入れないでください）。写真や動画はファイル名だけを使います。

    4. 発信テーマ（任意）

    発信する話題を、いくつか分けて登録できます（例: 温活／韓国ドラマ好きの50〜60代／60代の生き方）。投稿生成でテーマを空欄にすると、ここから「出す量」の割合で混ぜて作ります。「何日に1回は必ず」を選んだテーマは、その日数があいたら必ず入れます。1回の生成で入る必須テーマは各1本までなので、数日分をまとめて作ると2日目以降には入りません（毎日作るか、日を分けて作ってください）。1つも登録しなければ、今までどおりです。

    5. 宣伝したいもの（任意）

    期間が決まっているお知らせを登録し、「宣伝投稿を作る」を押すと、期間の毎日に1本ずつ（1日の本数を変えたときはその数）の投稿案が承認待ちに入ります。承認するまで外には出ません。期間の外の日時には予約できません。宣伝の投稿は読まれにくいので、1日1本をおすすめします。本文には、ふだんはURLを入れず「プロフィールのリンクから」と書きます。

    6. 運用

    1日の投稿数の目安: はじめは10本にしてください。1日30本は、スパムとみなされて規制を受けやすい数なので、この数にしないでください。アカウントが育って、フォロワーが増え、コメントなどの反応が安定して続くようになってから、少しずつ増やします（例: 10本を15本にして1週間様子を見る）。数を変えた日は、記録に残してください。規制の警告が出たら、すぐ前の数に戻します。この30本という数字は提供元の経験にもとづく目安で、Threads が基準を公開しているわけではありません。

    自動送信をONにしても、送られるのは「予約済み」の投稿だけです。承認待ちの投稿は送られません。

    コメント対応の自動化（サーバー起動中に裏で動く）

    自動返信がOFFのときも、コメント返信タブの「AIでまとめて下書き」で10件ずつ判定と下書きだけ作れます。送信は「この内容で返信する」を押したときだけです。ONにすると、AIが「返信する」と判定したものは間隔と上限の範囲で自動送信され、一覧に「自動返信」と表示されます。相手をユーザー名で呼ぶ書き方はしません。

    7. 出す前の安全確認の数値

    Threads は凍結の基準を公開していません。ここの数値はすべて暫定の目安です。小さくするほど早めに止まり、大きくするほど止まりにくくなります。ただし公式の上限（投稿は24時間で250件、返信は1,000件）より大きくはできません。ONとOFFは、概要の安全確認の欄で切り替えます。

    空欄のまま、または範囲の外の数字を入れて保存すると、保存が止まります。注意する一致率が止める一致率と同じか大きいときも止まります。直してからもう一度保存してください。
