# Threads運用アシスタント

Threadsの「リサーチ → 投稿生成 → 承認 → 投稿 → 分析 → 改善」を回すツールです。AIが作った文章は必ず人が承認してから外に出る「承認制」で動きます。コメント返信は、AIが判定して自動で返す運用にも切り替えられます（クレーム・営業・個人情報・金銭に触れるものは人に残します）。

あなたの PC の中で動きます（データもキーも PC の外に出ません）。操作はブラウザの画面か、Claude Code のチャットのどちらでもできます。

## インストール（Claude Code に1行貼るだけ）

### 準備するもの

| 項目 | 内容 |
|---|---|
| Claude Code | https://claude.ai/download からインストールしてサインイン（Claude Pro 以上の契約。文章の生成はこの契約枠で動くので追加費用はありません）。文章の生成に `claude` コマンドを使うので、ターミナル（CLI）版が要ります。デスクトップアプリだけの環境は未確認 |
| パソコン | Windows 10/11、または macOS。起動している間だけ自動処理（予約投稿・コメント返信）が動きます |
| Threads アカウント | 投稿に使うアカウント。提供元にユーザー名（@ から始まる名前）を伝え、届いた「テスター招待」を Threads アプリの 設定 → アカウント → Threads テスター招待 で承認しておきます |
| App ID と App Secret | 提供元から届く2つの値。Threads 連携のときに設定タブ「2. Threads連携」へ入れます（チャットには貼らない） |

Node.js は無ければインストール中に自動で入ります（Windows は winget、Mac は Homebrew。どちらも無い PC では https://nodejs.org から LTS 版を先に入れてください）。インストール中、Claude Code が「実行してよいですか」と聞いたら「はい」、Windows の「このアプリがデバイスに変更を加えることを許可しますか」にも「はい」。全体で3〜5分かかります。

### Windows

Claude Code のチャットに次の1行を貼って Enter:

```
以下のURLからThreads運用アシスタントのインストールスクリプトを取得して、内容を確認してから実行してください: https://raw.githubusercontent.com/joshicrea/joshicrea-threads-ops/master/install.ps1
```

### Mac

```
以下のURLからThreads運用アシスタントのインストールスクリプトを取得して、内容を確認してから実行してください: https://raw.githubusercontent.com/joshicrea/joshicrea-threads-ops/master/install.py
```

### インストールで起きること

1. プラグインが Claude Code に登録される（チャットから操作できるようになる）
2. 本体が `~/.claude/threads-ops/app/` に置かれ、データは `~/.claude/threads-ops/data/` に分けて保存される（更新しても消えない）
3. PC のログオン時に本体が裏で自動起動するよう登録され、その場で起動する
4. 終わったら Claude Code を閉じて開き直し（Node.js を今回入れた場合は、Claude Code を動かしているターミナルやエディタごと閉じる）、チャットに「はじめまして」と送るとセットアップ（発信者情報・AI の確認・Threads 連携）が始まる

### チャットからできること

「投稿案を作って」「承認待ちを見せて」「3番と5番を承認して」「コメントを見て」「要確認を見せて」「反応はどう」「設定を変えたい」。承認・公開・返信の送信は、あなたが本文を見て指示したときだけ行われます。画面（http://localhost:4173）の方が速い操作（大量の承認・設定・ログ）はそちらで。

## 手動で入れる場合（ZIP で受け取ったとき）

## 必要なもの

| 項目 | 内容 |
|---|---|
| PC | Windows 10/11（macOS でも動きますが、cmd ファイルは Windows 用です） |
| Node.js | LTS 版（20以上）。https://nodejs.org からインストール |
| AI | 次のどれか1つ。Claude Code（このPCにインストールしてログイン済み・追加費用なし）／Codex CLI（ChatGPT の契約で動く）／Gemini API キー／Claude API キー |
| Threads | 投稿に使う Threads アカウント。連携時に「テスター招待」の承認が要ります（下の「Threads連携」参照） |

置き場所は、OneDrive・Dropbox などの同期フォルダと Program Files を避けてください（同期ロックで保存に失敗したり、書き込み権限で止まります）。`C:\Users\<名前>\Threads運用アシスタント` のような場所が向いています。日本語のパスでも動きます。ZIP は必ず「すべて展開」してから使ってください（ZIP の中身を開いた状態で 起動.cmd を押しても動きません）。既に同期フォルダに置いて使い始めてしまった場合は、`停止.cmd` → フォルダごと移動 → `起動.cmd` の順で移せます（設定・データは `data/` ごと付いてきます）。

提供元とやり取りする値は次の3つです。

| 向き | 内容 |
|---|---|
| あなた → 提供元 | Threads のユーザー名（@ から始まる名前）。テスター招待に使います |
| 提供元 → あなた | Threads App ID / Threads App Secret / Redirect URI（設定「2. Threads連携」に入れる3つ）。既定値のままで動くと案内された場合は入力不要です |
| 提供元 → あなた | テスター招待（Threads アプリ側に届きます） |

## 起動・停止

| したいこと | 操作 |
|---|---|
| 起動する | `起動.cmd` をダブルクリック。黒い画面が開き、ブラウザで http://localhost:4173 が開きます。黒い画面を閉じるとサーバーが止まります |
| 止める | `停止.cmd`。黒い画面を閉じるだけでも止まります |
| PC を立ち上げたら自動で動かす | `自動起動を登録.cmd` を1回実行。次のログオンから黒い窓なしで裏で動きます（タスクスケジューラ「ThreadsOpsAssistant」）。使うときはブラウザで http://localhost:4173 を開きます。やめるときは `自動起動を解除.cmd` |
| 動いているか確かめる | ブラウザで http://localhost:4173 を開く。開かなければ止まっています |

起動.cmd と自動起動の両方を動かしても二重には起動しません（既に動いていれば、その旨を表示してブラウザを開くだけです）。ポート 4173 を別のプログラムが使っているときは黒い画面にその旨が出ます。その場合は 起動.cmd を右クリック → 編集で `node start.js` の前の行に `set PORT=4273` のように別の番号を足してください（画面のアドレスもその番号になります）。ただし Threads 連携の中継ページは 4173 に戻ってくる作りなので、番号を変えた状態では「Threadsと連携する」が通りません。連携は 4173 で済ませてから番号を変えるか、提供元に相談してください。

自動処理（予約投稿の送信・コメントの取り込みと返信・インサイトの取得）は、このサーバーが動いている間だけ働きます。PC がスリープ中や電源オフのときは止まり、次に動いたときに再開します。止まっていた間に時刻を過ぎた予約は、24時間以内なら再開時にそのまま送られ、24時間以上過ぎていたものは送らずに「エラー」にして知らせます（内容を確かめて予約し直してください）。

## 最初の設定（画面の「設定」タブ）

1. AI（文章生成）: プロバイダを選んで「接続テスト」を押します。Claude Code は、このPCで `claude` を一度起動してログインしてあれば追加設定なしで動きます。見つからないときは画面にその旨が出ます
2. Threads連携: 「Threadsと連携する」を押す → Threads の許可画面で許可 → 画面に戻ったら「再読み込み」。連携前に、提供元から届く「テスター招待」を Threads アプリの 設定 → アカウント → Threads テスター招待 で承認しておきます（承認していないと「The user has not accepted the invite」エラーになります）。Redirect URI と App ID / App Secret は提供元から案内された値をそのまま入れます（既定値のままで動く場合はそのままで構いません）
3. 発信者: 名前・プロフィール・文体ルール・CTA を書きます。ここが投稿の質を決めます
4. 運用: 予約時刻（日本時間）、予約投稿の自動送信、コメント対応の自動化、アクセスキー（任意）

## 使い方（1サイクル）

1. リサーチ: 「参考投稿」タブでキーワード検索（または手動貼り付け）→ 使う投稿にチェック → 「選んだ投稿の型を分析」。「Web参照元」タブで事実の根拠になる記事を集めることもできます
2. 投稿生成: 目的・テーマ・投稿日・本数を入れて「生成する」。参考投稿の型・Web参照元・過去の反応上位・文体ルールを踏まえた投稿案が承認待ちに入ります。本文が空の案や、参考投稿の丸写しに近い案はこの時点で捨てられ、ログに残ります
3. 投稿キュー: 本文を確認して「承認」。必要なら「編集」（本文・タグ・代替テキストを変えると承認待ちに戻ります）。承認済みは「予約する」か「今すぐ投稿」
4. コメント返信: 「コメントを取得」→「AIでまとめて下書き」→ 内容を直して「この内容で返信する」。自動返信をONにしている場合は、判定が「返信する」のものだけ裏で送られ、要確認のものが一覧に残ります
5. 分析・改善: 「インサイトを取得」→ カテゴリ別・時間帯別・投稿別の数値 → 「改善提案を生成」→ テーマ案を「生成に使う」で次のサイクルへ。公開から24時間未満の投稿は数字が育っていないので、平均と下位の集計から外しています

## 投稿の状態

| 状態 | 意味 | できる操作 |
|---|---|---|
| 承認待ち | AI生成・手動追加の直後 | 編集 / 承認 / 却下 |
| 承認済み | 内容確認済み・日時未確定 | 予約する / 今すぐ投稿 / 編集 / 却下 |
| 予約済み | 自動送信ONなら時刻に送信 | 予約解除 / 今すぐ投稿 / 編集 |
| 公開済み | Threadsに出た | 元投稿を見る（編集・削除不可） |
| エラー | 送信に失敗。理由が表示される | 編集 / 承認し直す / 却下 |
| 却下 | 使わない | 承認待ちに戻す / 削除 |

承認前の投稿は、画面からもAPIからも外部に送れません（サーバー側で強制）。送信の途中で PC が落ちても、次に動いたときに Threads 側の状態を確かめてから、公開済みに直すか送り直すかを決めます（同じ本文を二重に出さないため）。エラーになった投稿を承認し直して公開するときも、直近の自分の投稿に同じ本文が無いか確かめてから送ります。ただし、エラー後に本文を編集した場合はこの照合ができません（本文が変わっているため）。その場合はログに知らせが出るので、Threads 側に前回分が出ていないか見てから公開してください。

## コメント対応の自動化（設定「4. 運用」）

- 新着コメントの自動取り込み: 既定5分ごと。直近30日の投稿が対象
- AIのまとめ判定と下書き: 10件ずつ1回の呼び出し。クレーム・営業・個人情報・金銭・意味不明・事実確認が要る質問は「要確認」に残す。相手をユーザー名で呼ぶ書き方はしない
- 自動返信ON: 判定が「返信する」のものだけ、間隔（既定20秒）と1日上限（既定500・Threads の上限は1,000）の範囲で送る。一覧に「自動返信」と表示。Threads の上限に触れたら一時停止し、下書きは残す
- 自動返信OFF: 判定と下書きまで。送るのは人
- Threads アプリから手で返したコメントは「Threadsアプリで返信済み」として扱い、二重に返しません
- インサイトの1日1回自動取り込み

## アクセスキー（任意）

画面は同じ PC からしか開けません。同じ PC を他の人と共有している場合や、Tailscale などで外から開く場合は、設定「4. 運用」でアクセスキー（8〜128文字）を決めてください。以後、画面を開くとキーを聞かれ、そのブラウザだけが覚えます（ブラウザの「サイトデータを削除」で消えます。共有 PC では使い終わったら消してください）。空欄に戻すと不要になります。

## データと安全

- `data/db.json` に設定・投稿・コメント・インサイトがすべて入ります。APIキー・トークン・アクセスキーも入るので、このフォルダを人に渡さないでください
- `data/backups/` に1日1回、7世代まで自動で控えを取ります。`db.json` が壊れていたら、起動時に新しい控えから自動で戻し、壊れたファイルは `db.json.corrupt-<日時>` として残します
- `data/server-error.log` に失敗の記録が残ります（1MB を超えたら古い分から消えます）。キーやトークンの値はログに出ません
- 自動起動の出力は `data/autostart.log` に残ります

## アップデート方法

プラグインで入れた場合: インストールのときと同じ1行をもう一度 Claude Code に貼るだけです。データ（`~/.claude/threads-ops/data/`）はそのまま残り、本体だけ新しくなります。動いていた旧版はインストール中に止めて新版で起動し直します。貼ったあと Claude Code を閉じて開き直してください。

ZIP で入れた場合:

1. `停止.cmd` で止める（自動起動で裏で動いている場合も止まります。更新が終わるまでログオンし直さないでください。し直すと旧版が自動起動します）
2. 新しい ZIP を展開し、`data/` 以外のファイルを上書きする（`data/` は残す）
3. `起動.cmd` で起動する。画面右上にバージョンが出ます。設定やデータは引き継がれます

| 「Threads App IDが未設定です」 | 提供元から届いた App ID と App Secret を設定タブ「2. Threads連携」に入れて保存してから、もう一度「Threadsと連携する」 |
| 1行を貼ったら途中で止まった | 同じ1行をもう一度貼る。入っている分は飛ばして続きから進みます。Node.js の導入で管理者の許可を求められたら「はい」 |
| 起動.cmd を押しても画面が開かない | 黒い画面のメッセージ。「Node.js が見つかりません」なら Node.js をインストール。「既に起動しています」なら http://localhost:4173 を開く |

| 自動返信が動かない | 本体が動いているか（画面が開くか）と、設定「4. 運用」で「AIが判定して自動で返信する」が ON かを確認。ON でも要確認に分けられたものは送られません |
| アンインストールしたい | `~/.claude/threads-ops/app/アンインストール.cmd`（Mac は `アンインストール.command`）をダブルクリック。自動起動の解除 → 本体停止 → プラグイン登録の削除 → フォルダ削除まで自動。詳しくは同じ場所の `アンインストール.md` |

| 画面が「アクセスキーが必要です」と出る | 設定で決めたキーを入れる。忘れたときは `停止.cmd` で止めてから `~/.claude/threads-ops/data/db.json`（ZIP で入れた場合は `data/db.json`）の `accessKey` を空（`""`）にして `起動.cmd` |

| それでも直らない | `~/.claude/threads-ops/data/server-error.log`（ZIP で入れた場合は `data/server-error.log`）の末尾を提供元に送る（キーの値は入っていません） |

## 提供元・開発者向け

- AIプロバイダの実測: Claude Code（接続3秒/生成30秒・1回 約450トークン）／Codex CLI（接続30秒/生成31秒/Web検索34秒・1回 約6,900トークン。Codex 内蔵のコーディング指示を `model_instructions_file` でツールの短い指示に差し替えて 22,567→6,942）／Gemini API／Claude API（Web参照元の検索には使えない）
- Claude Code 経由の仕組み: `claude -p`（非対話モード）を専用の設定フォルダ `data/claude-config/` で起動する。利用者の `~/.claude/CLAUDE.md` やルールは読み込まず、ログイン情報だけを `~/.claude/.credentials.json` から片方向でコピーする。実体は `%USERPROFILE%\.local\bin\claude.exe` → npm グローバル → PATH 上の `claude.cmd`（中の cli.js を node で起動）の順に探し、shell は経由しない。環境変数 `THREADS_CLAUDE_CMD` で「コマンド 引数...」の形で明示できる（値が実在するファイルのパスなら空白を含んでいても分割しない）。Codex も同じ形（`data/codex-home`・`THREADS_CODEX_CMD`。`.js` のパスを指すときは node で起動する）
- Threads API: 長期トークン（60日）は期限の7日前から自動更新（サーバー起動中のみ）。送信中に中断した投稿の復旧は、直近50件の自分の投稿と本文一致で探し（公開後のメディアIDと permalink が取れる）、無ければコンテナの状態（PUBLISHED）で判定する。キーワード検索は Meta の審査を通るまで「自分の投稿」しか返さない（公式仕様・2026-09-20 実測 0件）。0件または権限不足のときは、Claude Code / Codex なら自動で Web検索経由（threads.com 限定の検索→投稿ページの読み取り）に切り替わり、公開投稿を最大8件取り込む。返信の上限は 1,000/日、検索は 2,200/日。DM の API は無い
- Redirect URI: Meta の設定フォームは localhost の URL を保存できない（Uninstall / Delete Callback URL が必須のため）。`relay/` の4ファイルを公開ドメイン（https）に置き、Meta の3欄とツールの Redirect URI にその公開URLを登録する。既定値は `https://bizcrea.com/threads/callback.html`（環境変数 `THREADS_REDIRECT_URI` で変更可）。中継ページはブラウザを `http://localhost:4173/oauth/callback` へ転送するだけで、コードは外部に残らない。詳細は [relay/README.md](relay/README.md)
- テスター招待: 審査前は、Meta アプリの「アプリの役割 → 役割 → テスター → Threads テスター」に利用者の Threads アカウントを追加し、利用者側で承認してもらう
- Meta のアプリ審査（公開投稿の検索・外部提供に必要）の出し方は提供元の手元にある `Meta審査申請/申請手順.md`（配布 ZIP には入れていない）
- 公開リポジトリ（1行インストールの取得元）: https://github.com/joshicrea/joshicrea-threads-ops 。中身はこのフォルダの git 追跡ファイルから `Meta審査申請/` を除いたもの。更新は `publish-github.ps1`（このフォルダの HEAD から書き出して commit・push する。data/ と Meta審査申請/ は入らない）
- 配布用 ZIP: `配布用ZIPを作る.cmd`（`data/`・`test/`・`Meta審査申請/`・`.git` を除外し、秘密が入りうるファイルが混ざっていないか検査してから作る）
- テスト: `npm test`（外部API を模擬。状態遷移・承認制の強制・二重投稿の防止・送信中断からの復旧・アクセスキー・OAuth の state 検証・コメント自動処理など）
- 画面のAPIは、固定ヘッダ `x-threads-ops` と Origin/Host の検査（別サイトからの偽リクエスト対策）に加え、アクセスキーを設定すると `x-threads-key` を要求する。同じ PC の別ユーザーからの操作は、アクセスキーを設定していない限り防げない
- PC を閉じている間も動かす（VPS 常時稼働）: [deploy/README.md](deploy/README.md)。Ubuntu 24.04 に `deploy/install.sh` で Caddy（https 自動）＋ systemd 常駐を入れる。アクセスキー必須・Redirect URI は `https://<ドメイン>/oauth/callback` を直接使う・Claude Code は `claude setup-token` の長期トークンを環境変数で渡す
- 外部提供版として足りていないもの: 利用者ごとのアカウント、秘密情報の暗号化保存、課金、監査ログ、利用規約への同意。現状は1台のPCで1人が使う前提
