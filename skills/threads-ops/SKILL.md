# 日常操作

前提: `threads_status` で本体に接続できていること。承認・公開・返信の送信は、利用者が本文を見て明示したときだけ行う（CLAUDE.md の決まり）。

## A-0. 伸びている投稿を調べる（リサーチ）

最初の投稿案を作る前に1回、その後は月に1〜2回が目安。「リサーチして」と言われたら行う。

1. キーワードを言われていればそれで、無ければ設定の発信テーマで調べる（聞かずに始めてよい）
2. `threads_research`（keyword は任意。keyword を渡すときは、設定のどのテーマの分かを theme に入れる）。1テーマで5〜10分ほど、最大20分で打ち切りなので、「裏で調べています。終わったらお知らせします」と伝え、待つ間は他の作業をしてよい
3. 数分おきに `threads_research_status`。終わったら、テーマごとの件数と、使うことにした投稿を「いいね・返信・フックの種類・冒頭」で並べ、元投稿のURLを添えて見せる。除外の理由もそのまま伝える
4. warnings に Chrome が見つからない旨があれば、Chrome（または Microsoft Edge）を入れるよう一言伝える。それまでは投稿の本文を貼ってもらう方法がある（画面の「手動で貼り付けて追加する」）
5. 止めたいと言われたら `threads_research_status` に cancel=true
6. 使う投稿は次の投稿案の生成に自動で入る（その回のテーマに合うものだけ）。本文を真似るのではなく、型（入り方・運び方・締め方）だけを借りる、と一言添える

## A. 投稿案を作る

1. 目的（例: 認知・信頼・申込）とテーマを1問ずつ聞く。両方言われていれば聞かない。本数は指定がなければ8。`threads_get_settings` の themes に使うテーマがあれば、テーマは聞かない（topic を省くと、設定のテーマを比率と「N日に1回は必ず」どおりに割り当てる）
2. `threads_generate_posts`（goal, topic（テーマ設定済みなら省く）, count, date）
3. 結果を「番号・カテゴリ・冒頭30字」で一覧にし、「全文を見たい番号」「承認する番号」「直したい番号」を聞く
4. 承認 → `threads_post_action` action=approve（番号ごとに id を対応させる）。却下 → reject。修正 → 直した本文を見せて了承を得てから `threads_edit_post`
5. 承認済みを予約するか聞く。予約 → `threads_post_action` action=schedule（日時指定があれば scheduledAt を ISO 8601・日本時間で）。「今すぐ」→ 本文を再掲して確認を取ってから `threads_publish_now`

予約投稿が実際に送られるのは、設定「予約投稿の自動送信」が ON で、本体が動いている時刻だけ。OFF なら「予約しましたが自動送信は OFF です。ON にしますか」と聞く。

### 期間つきの宣伝

1. 「宣伝したい」と言われたら、何を・いつからいつまで・1日何本（既定1）・本文にURLを入れるか（既定は入れずにプロフィールのリンクへ促す）を1問ずつ聞く。内容は本人の言葉のまま使い、書かれていない数字や特典を足さない
2. `threads_get_settings` の campaigns に足して、配列ごと `threads_update_settings`
3. `threads_generate_campaign_posts`（campaignId）。全部が承認待ちで入る。全文を見せて、承認するものを聞く（自動では承認しない）
4. 宣伝の投稿は伸びにくい。本数を増やしたいと言われたら、その旨を一言添える

### 安全確認で止まったとき

1. 投稿・返信の safety.level が blocked なら、`threads_safety_override` を confirm を付けずに呼び、本文と止めた理由（規則名・日本語の理由）を利用者にそのまま全文見せる
2. 直すなら直した本文を見せて了承を得てから `threads_edit_post`（本文を変えると、もう一度確かめる）
3. 利用者が本文と理由を見て「出す」と明示したときだけ confirm=true で呼ぶ。これだけでは公開されない
4. 続けて `threads_post_action` action=approve → action=schedule（予定の時刻が過ぎていたら scheduledAt を直す）。返信は利用者の指示で `threads_reply`
5. 公式上限の手前（G1・G11）は解除できない。時間をおけば出せる、と伝える。1日の上限（G2）は既定10本で、利用者が増やしたいと言えば safetyDailyPostLimit（1〜250）で変えられる。Meta は基準を公開していない、多くするほど止められやすくなる目安、と添える
6. 守備範囲を聞かれたら: 検査するのは本文・本数・間隔・自分の過去投稿との類似・リンクの割合・トピックタグ・個人情報らしい並び・危険な表現・返信の件数と繰り返しだけです。画像や動画の内容、通報、IPアドレスや回線、Instagram との連動、Meta 側の誤判定は検査しません。

### 発信テーマの注意

- 1回の生成で入る必須テーマ（N日に1回は必ず）は各1本まで。数日分をまとめて作ると2日目以降には入らない、と添える
- 戻り値の themeWarnings に「必須の発信テーマ「名前」の投稿が作れませんでした」があれば、そのまま伝えて作り直すか聞く

## B. コメント対応

1. `threads_fetch_replies` → `threads_list_replies`（status 指定なし）で件数を伝える
2. 未対応があれば `threads_draft_replies`。結果を「返信する n 件・要確認 m 件」で伝える
3. 下書きあり（drafted）は、相手のコメントと下書きを対で見せる。自動返信 ON なら「裏で順に送られます。止めたいものがあれば番号を」と伝える。OFF なら「送る番号を」と聞き、指示があったものだけ `threads_reply`
4. 要確認（held）は holdReason を添えて見せ、返信文の提案は出してよいが、送るのは利用者の指示があってから。対応しないなら `threads_set_reply` status=ignored
5. 相手をユーザー名で呼ぶ書き方はしない（本体の下書きも同じ決まり）

## C. 実績と改善

1. `threads_insights`（refresh=true）→ 閲覧・いいね・返信の上位3件と、カテゴリ別・時間帯別・テーマ別（byTheme）の傾向を3行で。テーマ別は閲覧数の平均で、フォロワーがどのテーマで増えたかは分からない、と添える
2. インサイト付きの公開投稿が3件以上なら `threads_suggestions` を提案。結果の nextTopics を「次の投稿案に使いますか」とつなぐ
3. 公開24時間未満の投稿は数字が育っていないので、本体が平均と下位の集計から外している。その旨を一言添える

### 型（1文目の入り方）の共有と記録

- 投稿案は、提供元が同梱する共有の型ライブラリ（patterns/patterns.json）から、発信者のテーマに合う型を最大3つ参考にして作られる。直近5本で使った型は後回しになる。本文は発信者の言葉で書き直され、型の骨子だけを借りる
- 作った投稿には型の種類（hookType: question／empathy／story／bold-claim／contrarian／list／other）と、使った型の id（patternId）が残る
- `threads_insights` の typeStats が型別の実績。本数・閲覧数の中央値・口座全体の中央値に対する比を出す。本数5未満の型は「判定不能」で比を出さないので、良し悪しを言わない。再投稿と公開24時間未満は入っていない
- `threads_suggestions` の結果に repeated=true があれば、直近の提案とほぼ同じ内容。「前回とほぼ同じ提案でした」と伝え、そのまま次の投稿案に流さない。recommendedHookTypes は提案が推した型

## D. 設定

- `threads_get_settings` で現状を見せてから、変える項目だけ `threads_update_settings`
- 自動返信・予約投稿の自動送信を ON にするときは「自動で外に出る」ことを一言添えてから
- Threads 連携・キー・アクセスキーは画面（http://localhost:4173 の設定タブ）で。値はチャットで受け取らない

## E. よくある状況

| 状況 | 対応 |
|---|---|
| 本体に接続できない | 「`~/.claude/threads-ops/app/起動.cmd`（Mac は `起動.command`）をダブルクリック」か「PC を再起動」。自分では起動しない |
| threads.expired が true | 画面の設定タブで「Threadsと連携する」を押し直してもらう。それまで予約投稿とコメント処理は止まっている |
| 投稿がエラー | error の原文を短く見せ、「承認し直して今すぐ投稿」か「本文を直す」かを聞く。本体は同じ本文が既に出ていれば送らずに公開済みに直す |
| AI の利用上限 | 時間をおいて再実行。プロバイダの切り替えは画面で |
| 「今日の予定は」 | `threads_list_posts` status=scheduled を日時順で |
